# Operational reports

Phase 6A reports use authorized committed server snapshots for one assigned branch. Owner, Admin and Manager can read sales, current inventory and recorded expenses. Cashier must explicitly select an own branch shift for sales activity; Inventory Staff can read current inventory. PostgreSQL enforces current membership, branch assignment and configured privileged MFA independently of Flutter's role controls. The design preview shows an explanatory empty state without business metrics.

Sales and expense dates describe UTC activity. The first date is inclusive; the selected inclusive last date becomes the following UTC midnight, so requests use `from <= timestamp < to`. Windows must be positive and at most 366 days. An arbitrary 366-day interval can intersect 367 UTC calendar dates. Each result includes the requested branch/window or inventory query/page, generation time and `server_posted` source. Each immutable currency remains separate across historical settings changes.

Sales originals contribute at their accepted `created_at`; accepted offline sales use their original capture time once posted. Refunds and voids contribute at their own creation time, even when the original sale predates the window. The shift filter describes the operation/drawer shift: a later reversal can belong to a different payout shift from its original sale. Split tender groups do not multiply sale or reversal totals. Net sales activity is posted sales less reversals and can be negative. Original subtotal, discount and tax remain original sale fields; the report does not calculate refunded tax allocation, net tax, inventory cost, COGS or profit.

Expenses contribute at server `occurred_at`; full compensations contribute at their own server creation time. Category and payment source derive from the immutable original. An older expense's compensation can produce a negative current-window net expense. External funds and cash-drawer sources stay distinct. Drawer expected/closing cash comes from the separate shift record. These reports describe recorded activity and do not establish provider settlement or a bank payout.

Inventory reports show current posted stock, including inactive products with stock history, visible deficits and observed zeros without recorded movement. Reorder levels retain their exact decimal representation. Low stock means an active product's whole quantity is at or below its reorder level. Product names/SKUs/units accept the existing catalog bounds of 160/64/32 characters. No unlike-unit grand quantity, cost-derived valuation or invented receiving history is shown. Pending and review-only offline evidence is excluded from all report totals.

## Verification and export

`SupabaseReportsRepository` checks the current verified actor before dispatch and after a response. It rejects foreign scopes, altered filters, unsupported currencies/tender/category/source labels, duplicate groups, nonintegral or unsafe numbers, malformed UTC times and contradictory totals. Money, quantity and counts remain within ±9,007,199,254,740,991; Dart uses `BigInt` for aggregate arithmetic. SQL overflow is an actionable narrower-window/filter error. Each server report uses one SQL snapshot rather than independently fetched totals and details.

Account/service/recovery changes discard previous results and ignore old responses. Branch changes remain available during loading and invalidate the earlier request. Cashier shift choices filter the authorized organization, branch and actor, with paged history; no sales report runs before explicit selection. Date/query edits clear the displayed result and its export. Current stock pages use validated lookahead records but display and export only the requested page. Flutter retains the shared client page-offset cap of 100,000; SQL independently accepts bounded offsets up to 1,000,000.

The CSV copy action serializes the displayed authorized snapshot, including scope, UTC generation/window, source, currency and current inventory page. It preserves signed numeric minor units and quotes text containing CSV delimiters. Text that could become a spreadsheet formula is prefixed with an apostrophe, including leading whitespace/control-character formula attempts. Export does not load another report or broaden access. Physical printing, provider links and all-page downloads remain outside this slice.

## Local validation

After sourcing `tool/dev_env.sh`, run `flutter test --no-pub test/reports` and `dart analyze lib/features/reports test/reports`. The focused suite covers source-backed PostgreSQL fixtures, exact arithmetic, split tenders, reversal-only windows, separate historical currencies, UTC bounds/daily groups, inventory deficit/inactive/no-movement/decimal-reorder observations, role/session/foreign-filter rejection, actual RPC serialization, stale actor/branch responses, pagination, clipboard CSV and 320px/desktop preview/empty/data/error layouts.

The final focused run passed all **80 tests** (53 contract/CSV/SQL-fixture, 13 adapter and 14 widget tests). Scoped analysis reported no issues. The daily-row regression expands a report containing the maximum exact amount at 320px; its responsive layout preserves the amount without a `ListTile` trailing-width failure.

The actual SQL responses are saved in `test/fixtures/reports_sql_contract.json` from the isolated passing harness. The SQL report suite separately exercises role/branch/MFA gates, immutable activity timing, exact overflow, pending/offline exclusion and concurrent snapshot consistency. See [PHASE6_CONTRACT.md](PHASE6_CONTRACT.md) and [VALIDATION.md](VALIDATION.md) for final phase-wide counts and deployment/hardware acceptance gates. Local tests do not establish deployed Supabase/PostgREST, provider settlement or Windows/Android hardware behavior.
