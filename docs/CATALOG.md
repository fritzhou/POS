# Product and category catalog

Phase 2 adds connected product and category administration through the scoped `CatalogRepository`. `ProductsPage` receives that repository, an optional `PeopleRepository` for supplier choices, the role from verified membership, and `isPreview`. With preview enabled, a missing repository, or no verified role, it displays an empty **Not Yet Connected** state and disables all catalog requests and writes. It does not generate product records or stock quantities.

Product queries pass the search term, optional category and active status to the repository. Search covers names, SKUs and barcodes. Results use a 20-record page, with server-provided `hasMore` and previous/next navigation. Changing a filter resets pagination. Late responses are ignored when a newer request or membership scope replaces them. Desktop widths show a horizontally scrollable table; smaller widths use product cards and scrolling, responsive editors. Categories have their own paged tab with active/inactive/all filtering.

Only verified Owner, Admin and Inventory Staff roles see enabled mutation controls, using `AppPermission.manageProducts`. Manager and Cashier views are read-only. Cashier presentation omits costs even if an incorrectly configured test adapter returns them; the server must independently omit and protect those costs. Presentation checks are a usability boundary, not an authorization mechanism.

Product creation and editing support names, unique SKUs, optional barcodes/category/supplier links, cost, selling price, unit, reorder threshold, active status and an optional image reference. Money uses exact decimal-to-minor-unit parsing: `0.29` becomes `29`, and more than two decimal places is rejected rather than rounded. Reorder thresholds accept up to four decimal places. Existing currency is preserved; new products use the repository's PHP default. The reorder threshold is a planning value and cannot change stock.

Category and supplier selectors request at most 100 choices. The page discloses when more exist. Existing links outside the returned choices are preserved and labeled as outside the list. A supplier repository is queried only when the verified role can view suppliers. Selection errors are visible with reload controls and prevent product editing until those choices can be refreshed. Linking choices beyond the first 100 in a new product requires a later searchable selector.

Image references must be organization-scoped Storage-relative paths. Schemes, query strings, empty path segments and `.`/`..` path segments are rejected. The adapter checks the organization prefix; editing also validates against the product organization. The page never uploads or downloads images and displays an **Upload Coming Soon** label. Storage bucket configuration, object authorization and image rendering are unfinished.

Save buttons wait for the repository response. While pending, inputs and dismissal controls are disabled. A failure keeps the editor open and displays a public error; unexpected exception details never reach the interface. Product edits, active-state changes and category edits supply the displayed revision to the repository. A revision conflict disables saving the stale editor and asks the user to close and reload. Deactivation keeps history and confirms the action before issuing the request. No local success is invented after an error.

The catalog has no editable stock field. Phase 3's separate Inventory module shows authorized branch balances and movement history and records receipts or adjustments; catalog price/reorder edits cannot change stock. The disconnected preview labels the ledger **Not Yet Connected**. Catalog mutations are online requests; offline catalog write authorization and queueing remain unfinished.

Widget tests in `test/catalog_widgets` inject fixture repositories only. They cover 320–1440 layouts, role restrictions, filters and bounded pages, exact money and image-reference validation, pending saves, sanitized errors, retry and revision conflicts. They do not establish a deployed Supabase project, live business records or physical-device behavior.
